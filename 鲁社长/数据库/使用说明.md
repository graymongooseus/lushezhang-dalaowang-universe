# 人物库使用与更新规则

`人物谱系.sqlite3` 是主数据库；CSV、JSON和人物档案由主库导出。不要把编辑导出文件当成已经更新数据库。

本库依据视频 veuNZX1lNco 建立，持续加入后续视频，最新已加入 oG93w6k-1DY；当前为 v8 多职业标签与视频证据模型。鲁社长为主播和来源人物。公开履历是额外检索所得，均与视频信息分别标明出处。资料不表示已经补齐所有历史职务或核验当前在任状态。

## 用户所需维度

| 维度 | 存储位置 | 规则 |
| --- | --- | --- |
| 主角名字、别名、身份 | people | 稳定人物ID，不因职位或名字变化而换ID；昵称不擅自合并为实名 |
| 统一主分类 | people.category、classifications、person_classifications | 每人至少一个有来源的职业标签，允许跨领域；头像色环以主标签着色，圈层归属另表记录 |
| 主派系／家族 | people.primary_faction_id | 每人必有展示值；未知使用“派系待定”状态占位，不推定待定者属于同一阵营 |
| 学历与教育经历 | education | 一人多条；院校、专业、学历、学位、学习方式、年份分别保存 |
| 最高学历、最高学位 | people.highest_education_id | 引用具体教育记录；学历和学位分开，博士学位不自动等于全日制博士学历 |
| 信息更新时间 | 各事实表的 updated_at、people.updated_at | 数据库维护时间；与来源发布日期、任职日期、关系发生时间分开 |
| 所属派系 | factions、faction_memberships | 多对多；允许同一人多重归属，记录有效时期、主张者、来源、归属强度及核实状态 |
| 不同年份／地区／职务 | appointments | 一人多段，允许兼任；年份不强行精确到月或日；未知离任时间不表示仍在任 |
| 最高岗位职务 | people.highest_appointment_id | 目前来源可支持的历史代表岗位，不等于现职；存在并列或不可比岗位时需解释，不能按字符串排序自动选择 |
| 与其他人关系 | relationships | 同一对人物可有多种关系和多个时期；有方向的关系不会自动反推 |
| 亲疏／评价编码 | relationships.affinity、affinity_scope | -100至+100；必须同时读取适用范围；公开评价不等于私人关系，尚无依据时为NULL |
| 关系强度 | relationships.strength | 1至5，只描述联系紧密程度，与友好／敌对及可信度分开 |
| 关系证据与争议 | relationship_evidence | 同一条关系可同时保留支持与质疑，不以一方覆盖另一方 |
| 其他动态与预测 | observations | 尚不适合写入事实履历的言论、预测或待核实信息 |
| 更新历史 | change_log、relationships.supersedes_id | 更新理由、前后值和关系版本保留，便于回溯 |

## “三国人物好感度”的记录方式

亲疏／对立值是分析标签，不是对真实心理的测量。仅在后续材料能支持判断时赋值，并注明方向、时期、依据和可信度；默认使用宽区间和25的步长，避免虚假精确。

| 值域 | 含义 |
| --- | --- |
| -100至-75 | 有持续、直接证据支持的强烈对立 |
| -50至-25 | 有材料支持的竞争或冲突 |
| 0 | 有依据判断为中性；不是未知的默认值 |
| +25至+50 | 有材料支持的合作或相互支持 |
| +75至+100 | 有多项材料支持的紧密联盟 |
| NULL | 未知、证据不足或无法判断 |

“联系强度”单独记录：1＝偶发接触，2＝有限重复接触，3＝持续共事或合作，4＝长期且直接的密切协作，5＝多项独立证据支持的核心相互依赖。对立双方也可能强联系，不能把强度当好感度。首次仅陈增光与习近平在宁德共事时期记3，其余留空。

可信度采用高／中／低／未评估，指当前证据对该条结论的支持程度，不等于某来源永远可靠。官方履历可支持任职事实，不自动证明私人关系；主播自述只证明其提出了相关说法，不直接证明内容真实。

## 人物分类与圈层卡片（v4）

职业标签包含官员、军方、商业、媒体、学者、演员、主持人、运动员、律师、歌手和其他名人。演员与主持人分开，每人可有多种职业标签；头像色环只表示主标签，多选筛选匹配任一标签；圈层用独立归属图呈现。外国国家元首与普通观众账号不作为当前人物节点，移除记录留在 excluded_people 供审计。

派系卡片记录名称、类型、核心／代表人物、定义、成员角色、证据、归属时期及可信度。政治网络、政治运动、商业网络、媒体协作圈、思想受众圈和学术网络有不同含义，不能互相混淆，也不等同于亲属家族。人物主派系用于浏览，其他归属仍可并存。

目前的“习近平政治网络”等名称属于本库分析分组。钟绍军的候选归属依据既有媒体转述，明确标为待核实；不是已经确认的个人政治忠诚。同为中国官员或曾经共事，不自动归为同一派系。

“鲁社长节目协作圈”仅录入主播及本期共同参与者；被赞赏者或观众不会自动成为成员。霍金的剑桥学术背景记作学术网络，不代表政治阵营。未知人物统一显示“派系待定”，该占位不生成关系边。

本期两个非空亲疏数值的适用范围均为“公开评价”：鲁社长对袁腾飞的表述编码+50，对刘仲敬编码+25。这是本库的粗粒度分析编码，保留褒扬和批评的原始语境摘要；不当作真实心理量表，不与私人好感或节目中的95–99评分等同，也不反推对方对主播的看法。

未具名人物写入 unresolved_mentions；字幕误写与正式别名分开处理。政治人物被并列提及、历史人物被拿来类比都不足以生成现实人物关系。

## 新视频入库流程

1. 完整阅读根目录《工作流.md》，完整读取视频并核对全部姓名；先保存逐段原创 Markdown 总结，包含细节、时间码、说法类型与未确认项，再更新数据库来源。
2. 匹配已有实体；不确定是否同名或同账号时保留待核对身份。
3. 分别新增教育、任职、派系、关系和其他线索，逐项绑定来源与时间戳。
4. 若出现相反说法，新增质疑证据；关系确实发生变化时，建立新关系版本并设置 supersedes_id，不删除旧证据。
5. 更正旧事实时在 change_log 记录前后值和原因；更新受影响人物的 updated_at。事件年份不明时不得用视频发布日期代替。
6. 根据可支持的履历更新最高学历及代表岗位引用；保留旧任职记录。
7. 用SQLite备份API备份后，在事务中提交更新；检查外键及完整性，再运行 export.py 更新阅读版。

运行导出（在本目录）：

```sh
python3 export.py
```

首次初始化脚本 initialize.py 已执行；数据库存在时会拒绝重新初始化，避免覆盖后续资料。schema.sql 是v1历史结构；migrate_v2.py 是已执行的一次性迁移；schema_v4.sql 是当前结构；migrate_v3.py、migrate_v4.py 也已执行，不可重复运行。不要在现有库上重复初始化或导入。v1完整数据库备份保存在“备份”目录。

常用只读查询：

```sql
SELECT * FROM person_overview WHERE 核心研究对象=1;
SELECT * FROM appointments WHERE person_id='p_ye' ORDER BY start_date;
SELECT * FROM relationship_overview WHERE 人物A='习近平' OR 人物B='习近平';
SELECT * FROM relationship_evidence WHERE relationship_id='r_ye_chen';
```

空值含义统一为“尚未掌握或未评估”。数据库收录更新时间不表示所有来源都更新到同一天。未来可据新增来源补齐钟绍军、董军、陈增光学历、完整履历及派系分析。


视频文字稿保存于 video_analyses，逐段细节保存于 video_segments，提及人物保存于 segment_people。网页和下载 Markdown 均由 SQLite 导出，视频播放时间与事件发生时间分别记录。
